# SP-Manager 1.0.21 — Refresh Button Audit & No-Message Fix

## Scope
Audited the supplied SP-Manager 1.0.21 source for every visible button labelled **Refresh** and removed notification/message calls from Refresh actions.

## Refresh buttons audited

1. Named Order / Takeaway — `refreshOrders`
   - Reloads `orders` from local storage.
   - No message/alert/notice after click.

2. Products — `refreshProducts`
   - Reloads products and normalizes stock-control fields.
   - Reloads categories, product groups and product-group categories.
   - Clears invalid/current product selection.
   - No message/alert/notice after click.

3. Inventory — `refreshInventory`
   - Reloads products and stock history.
   - No message/alert/notice after click.

4. Customers — inline Refresh handler
   - Reloads customers.
   - Clears selection/edit state if required.
   - No message/alert/notice after click.

5. Purchases — inline Refresh handler
   - Reloads purchases.
   - Clears an invalid selected document.
   - No message/alert/notice after click.

6. Payment Types — `onRefresh`
   - Reloads payment types from storage.
   - No message/alert/notice after click.

7. Discount / Promotion — `onRefresh`
   - Reloads promotions from storage.
   - No message/alert/notice after click.

8. Settings → Hardware — `refreshHardware`
   - Requests Local Agent status and printer list.
   - Automatically runs when the Hardware tab opens and every 5 seconds.
   - Manual Refresh invokes the same function.
   - No message/alert/notice is generated by the Refresh action itself.
   - Hardware connection failures are represented by the existing status state, not a Refresh popup.

## No change to other functions

Only Refresh handlers were adjusted to remove Refresh-success notifications. Product Delete, POS, Payment, Inventory, Customer, Purchase, Settings, and other existing functions remain unchanged.
